# BLIS M3.2 plan

This is the M3.2 plan. Table O gives the objectives, Table V the deliverables, and Table W (the next part) the
workstreams. **Table W is the execution order.** An agent can execute it end to end under the standing
authorization (Table A, design §13.7): the maintainer gives one input once (a Hugging Face token) and can revoke the authorization at any time. The requirements that follow are the source of truth; this
page is generated from them.

A **Proposal** item is the plan's default and is built as written unless review corrects it. An **Open** item has a
named default that applies until the maintainer decides.

## What M3.2 delivers

M3.2 has five objectives. Each is a promise about BLIS that a user or a reviewer can check. The eleven deliverables
in Table V are how M3.2 keeps them; the last column names the workstreams of Table W that build each one.

**Table O. The five objectives of M3.2, most important first.**

| # | Objective | What it means for a user of BLIS | Checked by |
|---|---|---|---|
| 1 | **Accuracy you can trust** | Accuracy improves, and every improvement is proven on held runs that nobody could tune against | every accuracy change passes the whole-run landing gate on held InferenceX units; the refit of both engines (Table W row 29) is the main accuracy change |
| 2 | **More of the real world is scored** | Many more real InferenceX and configiq runs are compared with BLIS, each at the best closeness grade it can reach | the coverage funnel per source and the count of scored anchor units on the dashboard |
| 3 | **Faithful to the engine a team actually runs** | BLIS models the vLLM or SGLang commit a team uses, including main, without waiting for a release | each engine module's upgrade report and its oracle tiers at the modelled commit |
| 4 | **One repository, clean boundaries** | A change that touches several parts lands as one pull request, and each part still keeps to its own job | the import-graph and path-reference checks of design Table 1 |
| 5 | **The teams' scenarios work now** | Mistral-Large-4 and Inkling-2-Small run on GB200, and what M3.1 left open is finished, with no new GPU experiments | the DC4 scenarios simulate with every coefficient's method named; each of the 150 carried issues is closed or moved into a Table W row |

**Table V. The eleven deliverables of M3.2, and the objectives of Table O each serves.**

| # | Deliverable | What changes for users and contributors | Objective | Table W rows |
|---|---|---|---|---|
| 1 | **One repository** | blis-substrate, blis-vllm and blis-sglang become directories of inference-sim. A change to contracts, an engine and the simulator is one pull request, with no chain of re-pins. blis-vllm's old compatibility code is removed first | 4 | 1, 2, 27 |
| 2 | **Any upstream commit** | An engine module models any vLLM or SGLang commit, not only a release. A model that lands upstream between upgrades is added as a backport. | 3 | 3, 4 |
| 3 | **Three new calibration sources** | The vLLM CI perf API, SGLang's nightly metrics and job logs, and SGLang's profiler traces calibrate both engines, which row 29 refits. Each run's settings come from its own records. These sources are training data only | 1 | 10, 13, 14, 18, 29 |
| 4 | **Many more scored points** | No age limit on scoring, a coverage funnel per source, and closed engine and table gaps. Scored InferenceX anchor units could grow from 238 to about 2,800, or up to about 4,700; configiq adds about 373 to 1,257 anchor units | 2 | 12, 15, 16, 17 |
| 5 | **A real held-out gate** | A new whole-run gate judges every accuracy change on held InferenceX runs, once per pre-registered change, and returns only aggregates. Before M3.2 no such gate runs | 1 | 25, 26 |
| 6 | **Honest accuracy figures** | Accuracy is published only on held-out units, with one definition of each statistic, a closeness grade per point, and slices by any recorded attribute. configiq is used only for scoring (Terms) | 1, 2 | 16, 19, 26 |
| 7 | **Clean lowering** | Lowering lives only in the engine modules; the catalog holds checkpoint facts only, and the rule layer is gone. A new model or engine touches fewer places | 3, 4 | 5, 27 |
| 8 | **Every supported model on every cluster the team uses** | Mistral-Large-4 and Inkling-2-Small on GB200, and every supported model on H100, H200, B200 and B300 over RoCE or InfiniBand, and on GB200 and GB300 NVL72 racks. A combination is refused only when the modelled vLLM or SGLang commit cannot run it, or it does not fit in memory. A value no data measures is priced by the most trusted fallback, and every point names its method. Each release publishes the support matrix | 5 | 6, 7, 9, 28 |
| 9 | **CI that fails only when the product is wrong** | Checks cover product correctness only. Nightly process checks and checks that read pull-request text go; review and merge are maintainer practice. Editing a pull request's text never changes its merge state | 4 | 22 |
| 10 | **Simpler everyday use** | Fewer commands, roles and nightly jobs, and one run by default (Table DC) | 4 | 8 |
| 11 | **What M3.1 left open** | The 150 M3.1 issues still open are each closed or moved into the row that owns them. The GB200 decode cost, the KV pool size and the other items moved to M3.2 by decision are finished, and blis-config-search#110 is split into four workstreams | 5 | 20, 21, 23, 24 |
